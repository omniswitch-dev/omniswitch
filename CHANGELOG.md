# Changelog

All notable changes to OmniSwitch will be documented in this file.

The format is based on Keep a Changelog, and this project follows semantic versioning once tagged releases begin.

## [Unreleased]

A hardening release: security fixes, verified bug fixes, new regression tests and safer defaults. Read "Breaking and behavior changes" before you upgrade.

### Breaking and behavior changes

- **Go 1.26.** A source build needs Go 1.26 or newer. Dependencies with known vulnerabilities are upgraded (pgx, gRPC, `golang.org/x/net`, `golang.org/x/text`, OpenTelemetry and others), and `govulncheck ./...` reports no vulnerabilities. The lint job uses golangci-lint v2, because v1 cannot type-check Go 1.26 code.
- **Loopback bind when auth is off.** When authentication is off and neither `OMNISWITCH_LISTEN` nor `gateway.listen` is set, the gateway listens on `127.0.0.1:8080`. An explicit non-loopback address with auth off logs a warning. Docker images set `OMNISWITCH_LISTEN=:8080`. The standalone `cmd/proxy` also defaults to `127.0.0.1:8080`.
- **`/metrics` follows gateway authentication.** Workspace- and organization-scoped callers get 403. Set the new `OMNISWITCH_METRICS_PUBLIC=true` to serve it without authentication and to all callers.
- **Stricter roles.** Viewers can no longer read `/api/keys`, `/api/virtual-keys`, `/api/users`, `/api/workspace-members`, `/api/configs` or `/api/config/raw`. Organizations and workspaces need `viewer` to read and `admin` to write. Writes (any method other than `GET`, `HEAD` or `OPTIONS`) to other `/api/*` routes need `admin`, except `/api/feedback`, which every role can use. A caller cannot create or delete a key that ranks above its own role, and a workspace-scoped caller manages only the keys of its own workspace. An organization-scoped caller (an OIDC caller with an organization claim and no workspace) lists only the keys of its organization's workspaces. When it creates a key, it must send a `workspace_id` of its organization: without it the gateway returns 400, and for a workspace outside its organization it returns 404. It gets 404 when it deletes a global key or a key of another tenant. A key without a workspace is global, and only global callers see it. Workspace- and organization-scoped callers get 403 on `/api/virtual-keys`, `/api/virtual-keys/rotate`, `/api/configs` and `/api/config/raw`, because these settings apply to the whole gateway. See also "Tenant isolation" under Security.
- **Control-plane limits.** `/api/*` request bodies are limited to 1 MiB (8 MiB for `/api/configs` and `/api/config/raw`); a larger body gets 413, also when it is sent without `Content-Length`. `/api/prompts/render` accepts only `POST`. Prompt rendering is single-pass, with limits on output and variable size. As before, a placeholder is filled only when its name matches a variable name exactly: `{{first-name}}` and `{{user.name}}` are filled, and `{{ name }}` (with spaces) does not match the variable `name`.
- **Client identity headers are removed.** The gateway deletes client-supplied `x-omniswitch-key-id`, `-rate-limit`, `-workspace-id`, `-organization-id`, `-role`, `-auth-method` and `-user-id` headers. `x-omniswitch-user-id` comes only from the OIDC subject.
- **OIDC.** Tokens without `exp` are rejected (30 seconds of clock leeway). An unknown `kid` refreshes the JWKS at most once per 30 seconds. EC keys are validated on their curve.
- **Strict environment parsing.** An invalid boolean, integer, number or duration stops startup and names the variable. Integer settings must be positive, except `OMNISWITCH_LOG_RETENTION_DAYS`, which accepts `0`.
- **Storage DSN validation.** `OMNISWITCH_DATABASE_URL` and `gateway.storage_url` must be `postgres://` or `postgresql://` URLs. Any other value, or `gateway.storage: postgres` without a DSN, stops startup. Before, the gateway silently used SQLite.
- **Policy replay files.** `POST /api/evals/policy` reads policies only from the new `OMNISWITCH_POLICY_DIR`. By default this is the directory of the MCP policy, but only when that directory is named `policies` (the default MCP policy gives `policies`). When the MCP policy is next to the gateway config or in the working directory, replay is off until you set `OMNISWITCH_POLICY_DIR`. Set it to `off` or `-` to turn replay off. Absolute paths, `..` segments and other extensions are rejected.
- **Bootstrap key.** `OMNISWITCH_BOOTSTRAP_API_KEY` no longer re-enables a disabled `bootstrap-admin` key or resets its spend. A changed secret rotates the stored hash. A missing bootstrap key is created only when no enabled owner or admin key exists.
- **Key budgets.** `budget_usd` is a lifetime cap, compared with the key's total spend. `monthly_cost_budget` and `monthly_token_budget` reset at the start of each UTC month. Before, key creation copied `monthly_cost_budget` into `budget_usd`, so a monthly budget also acted as a lifetime cap and never reset. A one-time data migration clears those copied values: it sets `budget_usd` to `0` on every key where `budget_usd` equals `monthly_cost_budget`. A lifetime cap that was set to the same value on purpose looks the same, so it is also cleared. The migration logs the affected key IDs and their old values (up to 100 keys) and an `UPDATE api_keys SET budget_usd = <usd> WHERE id = '<id>'` hint. If you set such a lifetime cap on purpose, set it again. The migration runs in the startup transaction and is recorded in the new `schema_migrations` table, so it runs only once per database. Older versions do not read that table: if you roll back, keys created by the older version get the copied value again, and a later upgrade does not clear them. Clear them by hand.
- **Budget checks.** When the gateway cannot read the budget state of a key (for example, on a store error), it rejects the request with 503, error type and code `budget_unavailable` and the message `budget state is temporarily unavailable; request rejected`. Before, it allowed the request. Keys known to have no budget are not blocked. Set the new `gateway.budget_fail_open: true` (`OMNISWITCH_BUDGET_FAIL_OPEN=true`) to allow these requests; the gateway then logs a fail-open request at most once every 30 seconds. A request also gets 402 `budget_exceeded` when its estimated cost or tokens would exceed the remaining budget, even if the budget is not yet used up. The estimate uses the request body for input tokens and `max_completion_tokens`, `max_tokens` or else 1024 for output tokens. The error message for this case gives the reserved amount and the estimate; the messages for an exhausted budget do not change.
- **Spend.** Key spend is charged whenever the upstream provider charged for the request, including a response that a guardrail denied after generation. Cache hits stay free.
- **Retries and the circuit breaker.** Without `retry_codes`, the router retries a provider only for 408, 409, 425, 429 and 5xx responses. Other 4xx errors go to the next fallback provider at once and do not open the circuit breaker. `Retry-After` is honored up to 10 seconds; a longer value moves the request to the next provider. In non-streaming chat, a non-retryable error now falls back to the next provider instead of failing the request. Client disconnects do not count as provider failures.
- **Streaming timeouts.** A route `timeout` on a streaming request limits the time to the first chunk, and after that it is an idle timeout between chunks. Long generations are no longer cut off. Provider streams no longer have an overall HTTP timeout.
- **Stream errors.** When an upstream stream fails, the gateway sends `data: {"error":{"message":"...","type":"upstream_stream_error"}}` and no `data: [DONE]`. `/v1/responses` sends `response.failed`, and `/v1/messages` sends `event: error`.
- **Stream usage.** The gateway asks every OpenAI-compatible upstream for stream usage (except Mistral and Azure On Your Data), so streamed requests are billed. The usage-only chunk goes to the client only when the client sets `stream_options.include_usage`.
- **Finish reasons** are normalized to OpenAI values. Refusals and safety blocks become `content_filter`, and unknown values become `stop`.
- **Guardrails.** When guardrail retries, reroutes or fallbacks are exhausted, the request fails with 403 `guardrail_triggered`. Redacted input is logged with the new `redacted` status. A config file with only `tool_rules`, `webhooks` or `llm_judges` is now enforced from startup; before, it took effect only after the first hot reload. A hot reload now removes the rules that were removed from the file.
- **Cache.** Semantic-cache keys include every request parameter other than the messages, and vectors are role-, order- and media-aware. Existing entries miss once after the upgrade.
- **A2A.** SSE frames are bare `data:` JSON-RPC responses with `status-update` and `artifact-update` results, without `event:` names. Tasks are visible only to the key and workspace that created them, and `CancelTask` stops the running inference. The gateway keeps at most 1,000 tasks per API key and workspace and 10,000 tasks in total (tasks still expire after one hour). When a limit is reached, the oldest finished task is removed first; if all tasks are still running, the oldest running task is removed and canceled. When an authorization policy is configured, an `/a2a` body larger than 1 MiB is denied with 403 `invalid request body for authorization policy`, as `/v1/*` bodies already were. Without an authorization policy, nothing changes; the general request limit stays `max_request_bytes` (default 10 MiB).
- **MCP JSON-RPC.** Batches, duplicate or case-variant members, invalid ids and a wrong `jsonrpc` version return `-32600`. Invalid `tools/call` params return `-32602`. Malformed JSON returns `-32700` with HTTP 400. Tool arguments can no longer lower the inferred environment or action.
- **MCP tool classification.** `action.name` is `delete` for every tool whose first word (in snake_case, kebab-case or camelCase) is `delete`, `del`, `remove`, `rm`, `drop`, `destroy`, `purge`, `truncate`, `erase`, `wipe` or `terminate`. A bare tool name gets an inferred action instead of `call`. `resource_type` and `type` arguments apply only when the inferred type is `unknown`. `action` and `operation` arguments can only escalate the action to `delete`, and `environment` and `env` arguments can only escalate the environment (to `production`). `session_id` and `agent_*` arguments no longer set the session or agent fields, and argument values are no longer copied into `metadata`. To migrate a CEL policy, match `action.operation` for the raw operation name (for example `action.operation == "drop_table"`), `target.name` for federated tools, and `args.<name>` for raw arguments. The policy engine logs a warning for a rule that compares `action.name` with a destructive verb other than `delete`.
- **OpenAPI-to-MCP.** A `body` argument is sent as the whole JSON request body. Before, it was wrapped as `{"body": ...}`.
- **SDK environment variables.** `OMNISWITCH_CONFIG` and `OMNISWITCH_SHADOW_PROVIDER` are renamed to `OMNISWITCH_CLIENT_CONFIG` and `OMNISWITCH_CLIENT_SHADOW_PROVIDER`, so they no longer collide with the gateway's own variables. An explicit SDK argument now wins over headers and environment variables.
- **Python SDK module.** The Python package installs only the `omniswitch` module. The `sentinel` compatibility module is gone, because it would clash with the unrelated `sentinel` package on PyPI. Replace `from sentinel import OmniSwitch` with `from omniswitch import OmniSwitch`; the `Sentinel` alias is still in `omniswitch`.
- **Tenant data.** Request logs and feedback written before the upgrade have no tenant, so only global callers can see them. A scoped caller that sends feedback with a `request_id` or `trace_id` of another tenant gets 404. The new `workspace_id` and `organization_id` columns of `request_logs` and `feedback` have a constant default, so adding them does not rewrite the tables.
- **Prompt namespaces.** Prompts belong to a workspace. Prompt names and versions are unique per workspace: the new unique index `idx_prompts_workspace_name_version` on `(workspace_id, name, version)` replaces `idx_prompts_name_version` at startup. Prompts created before the upgrade stay in the global namespace (`workspace_id` `''`), and only global callers can see them. A workspace-scoped key that used them must create them again in its workspace (a global caller can read them and send them again with `workspace_id` set). For a global caller, `GET /api/prompts` and `GET /api/prompts/versions` list only the global namespace, unless the request gives `workspace_id`.
- **Providers.** Gemini API keys are sent in the `x-goog-api-key` header, not in the URL. A config-file provider account now wins over an environment-variable preset with the same name or type. Groq's non-streaming timeout is 120 seconds. Cohere rerank uses the v2 API and bills search units.
- **Catalog prices.** `gemini-2.5-flash` and `o1-mini` prices are corrected. `gpt-5-mini`, `gpt-5-nano`, `gpt-4.1-mini`, `gpt-4.1-nano` and `claude-3-7-sonnet-20250219` are added. The decommissioned Groq `mixtral-8x7b-32768` and `gemma2-9b-it` are removed. Dated snapshots, Bedrock inference profiles and `@alias/` names resolve to their family price. OpenAI image prices follow the published per-image table.
- **Deployment.** Docker Compose enables authentication and restarts the gateway unless it is stopped. The first start on an empty database needs `OMNISWITCH_BOOTSTRAP_API_KEY` (the gateway exits without it); later runs can leave it unset, but a different value rotates the bootstrap owner key. The Helm chart (now version 0.3.0; `appVersion` does not change) generates a bootstrap key when auth is on, no OIDC JWKS URL is configured and no non-empty key is given (`bootstrap.generate`, default `true`), and keeps it across `helm upgrade`. `helm template`, Argo CD and Flux post-rendering cannot keep a generated key stable (each render rotates the owner key), so with those tools set `bootstrap.generate: false` and supply the key through `existingSecret` or `secrets`. The chart reads OTLP headers from a Secret (`observability.otel.headersSecret`) and sets `config.gateway.listen` to `:8080`. `.env.example` no longer turns auth off or enables MCP.
- **PostgreSQL upgrade.** The first start after the upgrade converts the old `REAL` columns to `DOUBLE PRECISION` and builds the new indexes inside the startup transaction, but only for OmniSwitch tables with 50,000 rows or fewer. For a larger table, the gateway builds the new non-unique indexes with `CREATE INDEX CONCURRENTLY` in the background after startup, one replica at a time (advisory lock); unique indexes are always built in the startup transaction. It leaves the `REAL` columns of a larger table as they are and logs a warning with the `ALTER TABLE` statement to run in a maintenance window. The rewrite takes about 9 seconds per 100,000 `request_logs` rows (about 3 minutes per 2 million rows) and locks the table. The type change touches only OmniSwitch's own tables, not other tables in the same schema. The startup migration checks columns and indexes before any `ALTER` or `CREATE INDEX`, so a normal restart takes no table locks. The migration uses `lock_timeout = 10s` and retries up to 4 times (after 1, 2, 4 and 8 seconds) on a lock timeout.

### Security

- **Tenant isolation.** The control-plane APIs for organizations, workspaces, users, workspace members, API keys, virtual keys and prompts now respect the caller's tenant. The dashboard API (logs, traces, metrics, provider metrics and cost analytics) and the feedback API are limited to the caller's workspace or organization. A caller with a workspace or an organization (a workspace-scoped API key, or an OIDC token with a workspace or organization claim) sees and manages only its own tenant; records of other tenants return 404. Trace reads no longer show shadow requests or feedback of another tenant that use the same trace ID. Global callers (authentication off, or keys without a workspace and organization) see everything, as before.
- **MCP request parsing.** Argument lookups ignore case, and case-variant protocol members (for example `Arguments` or `PARAMS`) are rejected (see "MCP JSON-RPC"), so a case variant can no longer bypass a policy. The environment is inferred from every resource-like argument (`repo`, `repository`, `table`, `database`, `resource`, `name`), and `production` wins.
- **A2A request parsing.** The gateway parses an A2A request once. Duplicate or case-variant members are rejected with `-32600`, so authorization and execution cannot see different models.
- **Upstream redirects.** MCP upstream and token-exchange requests no longer follow a redirect to a different origin. An OpenAPI path parameter of `.` is rejected.
- **OIDC key grace.** During an identity provider outage, the gateway accepts tokens signed with its cached JWKS keys for at most `identity.oidc.stale_if_error` (default 24h) after `cache_ttl`. A key that the provider removes during the outage stays trusted until the next successful refresh or the end of the grace. Set `stale_if_error: 0` (or `OMNISWITCH_OIDC_STALE_IF_ERROR=0`) to keep the previous fail-closed behavior.

### Added

- `OMNISWITCH_LOG_RETENTION_DAYS` deletes request logs, guardrail events and shadow requests older than the given number of days, once at startup and then every hour. The current UTC month is always kept. Expired semantic-cache entries are deleted every hour.
- Retries honor the upstream `Retry-After` header, and upstream errors keep their HTTP status (`provider.UpstreamError`).
- MCP policies can use the `target`, `session`, `metadata` and `args` CEL variables, `tool.full_name` and `action.operation`. MCP requests start an OpenTelemetry span and propagate W3C trace context. Audit events record the method, target, key, workspace, session and trace.
- `/v1/responses` supports function tools and typed input items. Embeddings and rerank honor the `x-omniswitch-config` header.
- Provider responses pass through `reasoning_content`, `refusal`, `logprobs`, token details, `system_fingerprint` and `service_tier`. Gemini thinking tokens are billed and reported as `reasoning_tokens`.
- `gateway.budget_fail_open` (`OMNISWITCH_BUDGET_FAIL_OPEN`, boolean, default `false`) and `gateway.budget_refresh_interval` (`OMNISWITCH_BUDGET_REFRESH_INTERVAL`, duration, default `5s`, allowed range 100ms to 10m). The refresh interval sets how often a replica reloads the budgets and the committed spend of a key from the store. A hot reload applies both settings.
- Go API: `provider.ErrStreamTruncated` (`upstream stream ended before completion`) is exported, so callers can detect a truncated upstream stream with `errors.Is`.
- The store tests also run against PostgreSQL when `OMNISWITCH_TEST_POSTGRES_DSN` is set.
- MCP targets accept `token_exchange` (RFC 8693: the OIDC caller's token is exchanged for a target token before each HTTP call), `timeout` and `metadata` in the gateway configuration. Validation rejects token exchange on stdio and OpenAPI targets, together with `forward_bearer_token`, or with an `Authorization` header. `client_id`, `client_secret` and `actor_token` expand `${VAR}` references, and a reference that expands to an empty value stops startup.
- `identity.oidc.stale_if_error` (`OMNISWITCH_OIDC_STALE_IF_ERROR`, Go duration, default `24h`, `0` to `168h`; `0` fails closed): how long cached JWKS keys stay usable after `cache_ttl` while a refresh fails. Go API: `gateway.JWTAuthenticatorConfig.StaleIfError` (the zero value keeps the fail-closed behavior).

### Fixed

- Bedrock Converse calls failed with 403 `SignatureDoesNotMatch` for versioned model IDs (which contain `:`) and inference-profile ARNs, because the SigV4 canonical URI was not encoded twice.
- Anthropic requests dropped `top_p` and `stop`, and sent `temperature` above 1. Anthropic, Gemini and Bedrock kept only the last system message. When a request sets both `temperature` and `top_p`, the Anthropic adapter now sends only `temperature`, because current Claude models (Sonnet 4.5, Haiku 4.5, Opus 4.1 and later) reject the combination with 400; `top_p` alone is still sent. The Bedrock Converse adapter applies the same rule to Claude model IDs (IDs that contain `anthropic.` or `claude`); other Bedrock models still get both.
- Gemini dropped assistant tool calls and tool results from the conversation, and ignored `stop`. Bedrock rejected conversations with two consecutive turns from the same role.
- SSE parsing ignored mid-stream error events and truncated streams, which then looked like a normal end.
- Concurrent SQLite writes failed at once with `SQLITE_BUSY`, so request logs and spend were lost under load. Writes now go through one connection with WAL mode and a busy timeout.
- PostgreSQL stored money and latency in 4-byte `REAL` columns, which lost precision. The columns are now `DOUBLE PRECISION` (on large tables you convert them; see "PostgreSQL upgrade"). Migrations run in one transaction under an advisory lock, so replicas can start at the same time. A startup migration that waits too long for a table lock fails after 10 seconds and is retried, so it does not hold up queries on that table.
- Timestamps were stored as variable-width text, so a monthly budget skipped the requests of the first second of the month and logs from the same second were out of order. They are now written in one fixed-width UTC layout; old rows stay readable. Old rows keep their old format, and timestamp columns are compared as text, so an old row from the second of the upgrade (for example `...:05Z`) sorts after a new row from the same second (`...:05.500000000Z`).
- An exact-cache entry could not be stored again after it expired, so every repeat of that prompt was a paid provider call.
- Every restart reset the spend of the bootstrap key.
- Concurrent prompt creates for one name could get the same version and fail. A unique index on prompt versions now prevents duplicates. If existing duplicate versions block the index, startup continues without it and logs a warning with the query that finds the duplicates (grouped by workspace); delete or renumber them, and the next start creates the index.
- Creating a user with an existing email returned a new ID that was never stored, so memberships created with it pointed at no user.
- The eval `datasets` and `experiments` tables did not exist, and experiments stopped when the HTTP request ended.
- `/a2a` ignored a hot-reloaded `max_request_bytes`.
- Every hot reload leaked the previous guardrail engine and its WASM scanners. The WASM guardrail module now compiles once per process in a shared runtime, and each engine uses a small pool of scanner instances.
- Guardrail rule indexes shifted when a pattern was not supported by the accelerator, so a match could be reported against the wrong rule.
- Invalid CEL route conditions failed silently on every request. They are now logged once at load and never match.
- Webhook and alert URLs (which can contain secrets) appeared in stored guardrail details and failure logs.
- The vault used a deterministic fallback master key when `crypto/rand` failed.
- Startup banner URLs were wrong for `host:port` listen addresses.
- `install.sh` used `sudo` even when the install directory was writable.
- An MCP target `Timeout` did not apply to calls forwarded to HTTP targets, so a hung upstream held the call for the fixed 2-minute header limit. The target timeout now limits the wait for the response headers (an event stream that has started is not cut), and the shared limit grows to the longest target timeout.
- Concurrent requests could together overspend the lifetime, monthly cost or monthly token budget of a key. The gateway now reserves an estimate before it calls the upstream provider and turns the reservation into the actual charge when the request ends. Budget checks no longer look up the key and add up the month's `request_logs` on every request. Each replica enforces budgets exactly for its own traffic and sees the spend of other replicas after the next refresh (`budget_refresh_interval`). For a model without a catalog price, the cost estimate is 0, so only spend already charged counts against a cost budget.
- Requests with the `x-omniswitch-config` header read the stored config from the database on every request. Stored configs are now cached in memory for 5 seconds (in a bounded LRU cache; unknown names are remembered for 2 seconds). A change through `/api/configs` applies at once on the replica that served it and within 5 seconds on other replicas. Deleted and renamed configs are removed from the cache. A hot reload of the file routes now also applies to requests that use a stored config.
- A config file hot reload reset open circuit breakers. The gateway now replaces the breaker only when `circuit_breaker_failures` or `circuit_breaker_cooldown` change. Requests that use a stored config share the circuit breaker of the base router.
- A half-open circuit breaker let every request through to a recovering provider. It now admits one probe request at a time; other requests use the fallback chain, as for an open circuit. The probe's success closes the circuit and its failure opens it again for a new cooldown. A probe that ends because the client cancelled frees the slot, and a probe that reports nothing within the cooldown counts as lost. Retries against the same provider stop when its circuit opens.
- Shadow traffic used a circuit breaker with a fixed 5 failures and 60 seconds. It now uses `circuit_breaker_failures` and `circuit_breaker_cooldown`, and a reload that changes them rebuilds the shadow breaker. Shadow traffic keeps its own breaker, so shadow failures never open circuits for client traffic.
- OIDC: an identity provider outage rejected every OIDC caller once the JWKS cache expired, and each request started a new fetch. The gateway now keeps verifying tokens with the cached keys during the `stale_if_error` grace. An expired cache is refreshed in the background, so requests do not wait for a slow JWKS endpoint. Failed fetches back off from 1 second, doubling up to 1 minute, and the backoff resets on success. During the backoff, requests without usable keys fail at once with the last fetch error.
- A client that disconnected during a stream could be logged as a provider stream error (`provider stream error: context canceled`). It is now always logged as `client disconnected before the stream completed`.
- Streaming `/v1/responses` did not deliver tool calls, so a streamed tool call gave an empty completed response. It now sends `response.output_item.added`, `response.function_call_arguments.delta`, `response.function_call_arguments.done` and `response.output_item.done` events for each function call, and `response.completed` lists the message and `function_call` items in `output`, as the non-streaming response does.
- Streaming `/v1/messages` now sends `tool_use` content blocks (`content_block_start`, `input_json_delta`, `content_block_stop`) after any text block when the routed model calls a tool, with `stop_reason: tool_use`.
- MCP notifications got JSON-RPC responses. The proxy now answers a notification with 202, or with 403, 400 or 502 and an error body without an `id`. `notifications/cancelled` reaches stdio servers with the correct request ID. Audit records are kept when the client disconnects. Shutdown also kills the processes that stdio servers start. Synthetic OpenAPI tools use the configured target name prefix, and their `tools/list` decisions are audited.
- Helm: a release that authenticates only through OIDC (`config.identity.oidc.jwks_url` or `secrets.OMNISWITCH_OIDC_JWKS_URL`) no longer gets a generated owner API key, and `bootstrap.generate: false` no longer fails rendering for it. An empty `secrets.OMNISWITCH_BOOTSTRAP_API_KEY` counts as not set; before, the chart rendered an empty key, and the gateway then failed on first start.
- Helm: `observability.otel.headersSecret.key` defaults to `headers`, so a value for `headersSecret.name` alone no longer fails rendering.
- Docker Compose: `docker compose config`, `ps`, `logs` and `down` no longer fail when `OMNISWITCH_BOOTSTRAP_API_KEY` is not set.
- The Helm NOTES, the chart README and `docs/DEPLOYMENT.md` said that the semantic cache stays local in PostgreSQL mode. Exact and semantic cache entries are stored in PostgreSQL and shared by all replicas.

### Changed

- Deleted the outdated `comparison_iter5.md` and `comparison_iter7.md` notes. The 27 competitor claims that cited only them are now "Unknown" in `docs/comparison/COMPARISON.md` until someone checks them against vendor sources.
- Removed the dangling `website` gitlink. The site lives in the `omniswitch-dev/omniswitch-website` repository.
- An upstream stream that closes without any chunk is now a failed attempt (`upstream stream ended before completion`). The router retries it or falls back as for other stream-start failures, it counts toward the circuit breaker, and the request gets 502 when no provider succeeds. Before, it was logged as an empty successful response.
- Budget alerts fire when a charge is recorded. An alert for a monthly cost budget uses the key label `<key id> (monthly YYYY-MM)`.
- `POST /api/users` accepts optional `workspace_id` and `role` fields that add the user to a workspace in the same call. Workspace- and organization-scoped admins must create users this way (for a workspace-scoped admin, `workspace_id` defaults to its own workspace). If the email already exists, the existing user is added to the workspace, and its name and metadata do not change. Scoped admins cannot create organizations. Workspace-scoped admins cannot create workspaces, and organization-scoped admins create workspaces only in their own organization. A scoped admin cannot grant a membership role above its own role or change a member whose role is above its own.
- `.env.example` no longer sets `OMNISWITCH_*` overrides that repeat the built-in defaults, so your edits to the config file take effect when the file is loaded as `.env`. Only the provider key placeholders, `OMNISWITCH_CONFIG`, `OMNISWITCH_BOOTSTRAP_API_KEY` and `OMNISWITCH_VAULT_KEY` stay set. The file now lists `OMNISWITCH_BUDGET_FAIL_OPEN`, `OMNISWITCH_BUDGET_REFRESH_INTERVAL`, `OMNISWITCH_METRICS_PUBLIC` and `OMNISWITCH_POLICY_DIR`. If you copied the old file, remove the overrides that you do not want. The old file set `OMNISWITCH_OTEL_INSECURE=true`; the default is `false`.
- The Docker image is built with `golang:1.26.9-bookworm` instead of a floating minor-version tag, so builds always use the Go release that `toolchain go1.26.9` in `go.mod` pins.

## [0.2.0-beta.1] - Unreleased

First public beta. Focused on making the install and first-run path trustworthy, filling in agent-protocol and storage gaps from 0.1.0, and standing up community/security scaffolding ahead of the public announcement.

### Added

- PostgreSQL shared-state storage driver, provider presets, MCP trace context propagation, and a Helm chart for Kubernetes deployments.
- OpenAPI-to-MCP conversion so any OpenAPI-described service can be exposed as MCP tools, a `bench` tool, and a proxy-overhead benchmark.
- A2A v1 task lifecycle (create, poll, cancel) with single-shot SSE for task updates (one status and artifact sequence per request; no token streaming or resubscribe).
- Guardrail fallback reroute action and automatic retries for guardrail webhook calls.
- RFC 8693 token exchange in the MCP proxy library, for delegating identity into federated MCP targets. It is available to Go embedders through `TargetConfig.TokenExchange`.
- Storage and handlers for eval datasets and experiments, next to the existing policy replay endpoint. Only policy replay (`POST /api/evals/policy`) is mounted in the gateway; the experiment scorer is a placeholder.
- First-run reliability, CLI, and health-check fixes so a freshly downloaded binary starts with only `OPENAI_API_KEY` set: MCP is disabled by default, an embedded default policy is used as a fallback when MCP is enabled without an explicit policy path, `omniswitch version`/`validate-config`/`--help` subcommands, and `/healthz`/`/readyz` HTTP endpoints for liveness/readiness probes (tracked in the sibling first-run workstream; see `ROADMAP.md`).
- Community, governance, and security scaffolding: `SECURITY.md` with supported-versions table and private vulnerability reporting, `SUPPORT.md`, `GOVERNANCE.md`, `MAINTAINERS.md`, `CODEOWNERS`, `.github/dependabot.yml`, a beta-feedback issue form, and an install-verification GitHub Actions workflow.

### Fixed

- Resolved an `err` redeclaration bug in `ChatCompletions` that had broken the streaming response flow.

### Changed

- `gofmt` formatting cleanup across the eval, store, and gateway packages (no behavior change).
